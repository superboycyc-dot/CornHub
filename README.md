# CornHub

Hack the Harvest 黑客松项目。我们用卫星时间序列预测玉米田的收割用途（青贮或籽粒），估算区域面积和产值，并找出最值得人工核查的田块。

**当前进度 · 2026-11-14**　启动阶段。五个席位待认领。下一次讨论优先确定研究地区、收获年份、真实用途标签来源和演示范围。

## 五条成员分支

| 分支 | 负责内容 | 交给下一位成员的成果 |
| --- | --- | --- |
| `member/01-data` | 数据与田块边界 | 数据来源和许可、田块 ID、年份、面积、用途标签及来源、可复现的小样本 |
| `member/02-features` | 遥感与数据处理 | 按田块和年份关联 Sentinel-2、NDVI 时间序列，输出特征表、有效观测次数和缺失标记 |
| `member/03-model` | 分类与可信度 | Random Forest 基线、独立验证集、预测及校准后的青贮概率、F1 与 Brier Score |
| `member/04-analysis` | 区域统计与经济分析 | 按面积和概率汇总用途，列出产量与价格假设，比较优先核查与随机核查的效果 |
| `member/05-demo` | 地图、展示与答辩 | 可点击的田块地图、区域汇总、核查清单、演示脚本和 PPT |

每个席位对应一名成员及其 AI。收到账号后由管理员登记。分支分工属于团队约定，成员获得的是仓库级协作权限。

## 从第一次讨论到交付

1. **确定样区。** 数据成员核实边界、年份和真实收割用途能否匹配。若标签不足，缩小样区或交付探索性演示，在地图和 PPT 标注证据局限。
2. **打通一个样例。** 前两条分支约定以田块 ID 和年份连接数据，统一面积单位。先交付一组能从边界追溯到观测记录的样例；展示成员可用标明为模拟的数据并行搭建地图。
3. **训练与验证。** 模型成员记录数据划分、特征、运行命令和版本。分开训练、概率校准及最终评估数据，检查同一田块跨集合造成的信息泄漏，输出逐田预测和评估报告。
4. **形成区域结论。** 分析成员以“田块面积 × 青贮概率”估计青贮面积，汇总籽粒面积。记录缺测覆盖范围、价格来源、单位及敏感性。使用保留标签回放相同核查预算下两种核查策略的区域估计误差。
5. **集成与演示。** 地图接入同一批预测，点击田块能看到用途概率、观测质量及核查理由。主控 AI 抽查地图与汇总表数值，复跑样例，汇总模型、报告、网站、PPT 和已知限制，在主线标记演示版本。

## 怎样维护主线

`main` 保存已经集成的成果，本页记录里程碑。每次把讨论结果发给主控 AI，它将决定整理为“日期、决定、负责人、验收条件”，把待办拆成 GitHub Issues，记录依赖和阻塞。成员 AI 从自己的固定分支同步最新 main，完成一个可验证的改动后向 main 提交 Pull Request，附关联 Issue、产物和验证结果。主控 AI 审查接口、复现结果、处理冲突并合并，更新进度。合并后保留五条分支供下一轮继续使用。

仓库所有者掌握 GitHub 管理权限；主控 AI 在获授权的会话内使用该权限协调工作。需要 DeepSeek 等模型参与时，由所有者指定任务、可共享材料和模型，再把结果纳入同一审查流程。

## 明天如何加入

1. 成员把 GitHub 用户名和拟认领席位发给所有者。
2. 所有者打开仓库 **Settings → Collaborators → Add people**，核对账号并发送邀请。这一步即表示批准。
3. 成员登录被邀请的 GitHub 账号，在邀请邮件或通知中接受，再用连接该账号的 AI 打开仓库。所有者可在 Collaborators 确认邀请状态。

**成员复制给自己的 AI**

> 我要加入 superboycyc-dot/CornHub。请确认当前连接的 GitHub 用户名，检查这个仓库的邀请。有邀请就帮我接受并验证可以读取 main；如需本人操作，请给我入口。若尚未被邀请，请生成一条我能转发给所有者的消息，写上用户名和拟认领的席位【编号】。取得访问权后，阅读 README，切换到管理员分配的分支，告诉我首项交付物和验收条件。

**所有者复制给主控 AI**

> 我批准 GitHub 用户【用户名】加入 superboycyc-dot/CornHub，分配到【分支】。请邀请该账号为协作者，核实是待接受还是已加入，更新席位记录，并为该成员建立第一项任务。

**每次讨论结束后**

> 今天决定了【内容】，仍待确定【问题】。请更新 CornHub 主线进度，按五条分支分配任务，写明每项的输入、交付物、依赖和验收条件，并把对应链接发给我。
